\section{视觉语言模型}

视觉语言模型（VLM）将视觉编码器与大语言模型对齐，实现了跨模态的理解和文本生成。LLaVA\cite{llava}（Large Language and Vision Assistant）是一个代表性的开源 VLM，它用 Vision Transformer（ViT）做视觉编码，LLaMA 做语言解码，中间通过线性投影层连接两个模态。LLaVA v1.5 的 7B 版本经过视觉指令微调后可以接受图像和文本的联合输入，输出自然语言回答。

这类模型在实际部署中有一个普遍的局限：它们对输入图像的裁剪质量非常敏感。在本文的三维物体标注场景中，物体裁剪区域的尺寸通常只占原始图像的 5\%--15\%，且包含大量背景噪声。面对这种低质量的输入，LLaVA 倾向于输出场景级别的感官描述（"自然光洒满整个空间"）而不是物体级别的属性描述（"靠墙的棕色木桌"）。这个现象并非说明 LLaVA 缺乏物体识别能力——事实上经过指令微调的 VLM 完全能够输出精确的物体类别——问题在于默认的生成模式没有对模型施加足够的输出约束。本文第三章的 prompt 优化工作正是基于这个认识展开的。

在本文的管线中实际使用的文本生成模型是 Qwen2.5\cite{qwen2_5} 系列，这是阿里巴巴 Qwen 团队发布的开源大模型家族，参数规模从 0.5B 到 72B。Qwen2.5-3B 在本文中承担了主要的推理工作：它的 GGUF 量化版本（Q4\_K\_M）仅占 1.9 GB 显存，MMLU 基准达到 65.6 分，推理速度远快于更大规模的变体。实验中系统比较了 3B、7B 和 14B 三个版本，发现在结构化 JSON 输出这类"格式约束强、语义复杂度有限"的任务上，额外的模型参数带来的质量增益微乎其微，但速度损失却相当可观。

在三维感知方面，An 等人（ICLR 2025）的工作\cite{multimodal_3d} 证明了将 CLIP 提取的文本特征与点云数据融合可以显著提升 few-shot 三维语义分割性能，在 ScanNet 和 S3DIS 上都达到了当时的最优结果。这个工作为本文后续引入深度信息作为额外描述模态提供了直接的参考路线。

\section{思维链推理}

思维链（Chain-of-Thought，CoT）提示技术让语言模型在输出最终答案之前先生成中间推理步骤。Wei 等人首次系统化了这个方法：在 GSM8K 数学数据集上，给 PaLM-540B 提供 8 个 CoT 示例后，准确率从 34\% 提升到了 57\%。CoT 之所以有效，本质上是因为它充当了模型的"草稿纸"——复杂问题被拆成子步骤后，每一步的计算深度降低，整体成功率高。

传统 CoT 的一个突出问题是它需要人工设计 Few-shot 示例，这个过程既耗时又对示例质量敏感。Zhang 等人提出的 Auto-CoT\cite{auto_cot} 用聚类采样的方式自动生成演示来应对这个问题：先把待处理问题聚成 K 个类别，每类挑代表性样本，让模型自己生成推理链，然后用这些自动生成的链作为下一轮的 CoT 示例。在多个推理基准上，Auto-CoT 的效果接近甚至超过了人工设计的 CoT。

对本文方法设计影响最直接的是 Cheng 等人\cite{chain_of_thought} 在 2025 年的一个重要重新审视。他们发现，对于 Qwen2.5 这种级别的大模型，给 CoT 示例不仅不能提升性能，有时反而会降。通过一组精妙的替换实验——把示例中的推理步骤换成无意义的占位符，只要输出格式（如 \texttt{\textbackslash boxed\{\}}）还保留，模型表现和完整示例几乎没有差别。注意力可视化进一步表明，解码时模型的注意力几乎全部集中在问题指令上，示例区域呈现出明显的低注意力分布。这意味着，对大模型来说，与其花精力设计完美的示例，不如把输出格式约束说清楚。本文第三章中只用了 system prompt 和严格的 JSON Schema 约束来做结构化输出，没有依赖任何 Few-shot 示例，正是基于这个结论。

Zhou 等人\cite{design_rationale} 在软件架构决策理由生成这个任务上的对比实验从另一个角度支持了这个结论。零样本方法在精确度（0.278 vs 0.237）和 F1（0.381 vs 0.351）上都优于 CoT，而且推理更快。CoT 生成的论证数量确实多了 26.7\%，但这些额外条文大多是泛泛之谈，缺少对具体架构决策的针对性分析。

\section{Code2Logic：游戏逻辑驱动的数据合成}

Tong 等人提出的 Code2Logic\cite{code2logic}（NeurIPS 2025）是本文方法论的核心来源。它的基本洞察很简明：游戏源代码中的状态机、碰撞检测和胜负判定本身就是结构化的事实，每一步合法操作和每一个状态转移都是定义明确的。让大语言模型读游戏代码并按照模板生成问答对，就能零边际成本地自动化产出大量高质量标注数据。

Code2Logic 的数据生成流程分三个阶段。首先是代码构建阶段，LLM 根据自然语言描述输出可执行的游戏代码——例如只需一行 prompt 就能为推箱子游戏生成包含完整状态空间和动作逻辑的 Python 程序。其次是模板设计阶段，从游戏逻辑中提取三类问答模板：Target Perception（如"棋盘上有几个红子？"）、State Prediction（如"走这步后黑子会到哪？"）和 Strategy Optimization（如"最少几步获胜？"）。最后是数据引擎阶段，把游戏代码作为生成器，批量跑参数组合来产出问答对。每款游戏大约需要 7.5 小时的初始开发投资，之后零边际成本。GameQA 数据集最终包含 30 款游戏、158 项任务和 14 万条问题。

GameQA 的实验揭示了几项关于游戏数据驱动泛化的关键发现。首先是游戏多样性的作用：用 20 款游戏训练的模型比只用 4 款的域外任务准确率高 1.8 个百分点，说明接触更多样的游戏逻辑确实促进了更鲁棒的表征学习。其次是数据量效用的反直觉规律：在几何任务上，0.5k 样本训 10 轮比 5k 样本训 1 轮效果更好（+2.5\%），提示近域任务需要深度拟合而非广度覆盖。GRPO 强化学习策略被证实是关键训练手段，其过程奖励机制使感知错误率降低 19.2\%、推理错误率降低 11.5\%。

Code2Logic 的明显局限在于，它的完美标注完全建立在游戏代码的显式逻辑之上——物体坐标和交互规则都是代码精确指定的。真实物理场景中，这些信息处处是模糊的：物体需要从传感器数据中分割出来，空间关系需要通过模型推断，噪声和遮挡无处不在。本文的工作正是朝着桥接这个差距的方向进行的。

\section{三维场景图构建}

三维场景图把场景表示为结构化的图——节点代表物体实例，边编码空间或语义关系。相比于二维场景图，三维版本需要额外处理深度信息、几何约束和视角变化。Concept-Graphs\cite{conceptgraphs} 是这个方向上有代表性的工作，它整合了三个核心组件来实现从 RGB-D 到场景图的端到端构建：GradSLAM\cite{gradslam} 提供可微分的 SLAM 前端，Grounded-SAM\cite{grounded_sam} 组合 Grounding DINO 和 SAM 做开放词汇检测和精细分割，CF-SLAM 将二维分割结果通过相机参数投影到三维空间进行聚类和建图。Replica 数据集\cite{replica} 为这类工作提供了标准化的评估平台，包含 18 个高精度重建的室内场景，每个场景配备约 2000 帧 RGB-D 图像和运动捕捉的相机轨迹。本文使用了其中 7 个场景。

\section{合成数据与域随机化}

合成数据通过计算机图形学生成带完美标注的训练数据，在目标检测、语义分割和深度估计等任务中被广泛用于弥补真实标注的不足。域随机化在合成数据的基础上进一步提升了模型的泛化能力，核心做法是在仿真环境中对非本质属性进行随机扰动，使模型学到对这些变化不敏感的鲁棒特征。本文在 Isaac Sim 的场景生成中使用了三种随机化：物体位置随机化（带碰撞检测）、材质颜色随机化（三套预设变体）和光照参数随机化（色温和强度的连续采样）。NVIDIA Isaac Sim\cite{isaac_sim} 是一个基于 USD 格式的仿真平台，支持 RTX 光线追踪和无头模式 Vulkan 渲染。在本文中它的角色不仅是数据生成器，更是标注质量的验证工具：合成场景中的精确 ground truth 为 Concept-Graphs 推断标注的精度评估提供了可量化的基准。

\section{本章小结}

视觉语言模型提供了跨模态理解的基础能力，思维链推理研究明确了零样本结构化提示的优越性，Code2Logic 验证了模板化数据合成的可行性，三维场景图技术给出了从传感器到结构化表示的工程链路，合成数据方法补充了验证环节。本文的工作把这几条线串在了一起，核心是把 Code2Logic 的方法论从 2D 游戏迁移到 3D 场景并在仿真环境中做可量化的结果验证。
